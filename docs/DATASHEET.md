# Datasheet for MuraTrace (v1.0)

Following Gebru et al., "Datasheets for Datasets".

## Motivation
- **Purpose.** A benchmark for display Mura inspection beyond binary detection: scale-wise segmentation of five Mura classes, graded SEMU visibility prediction, and process-trace attribution (which process step, tool, fault mode and time window caused a defect). Real defective panels and their process records are confidential and rarely releasable; MuraTrace composites physically motivated synthetic defects onto real defect-free panel backgrounds so that appearance and ground-truth cause are paired by construction.
- **Creators.** Sugyeong Lee (Department of Semiconductor and Display Engineering, Sungkyunkwan University).
- **Funding.** The dataset was created without external funding.

## Composition
- **Instances.** 540 synthetic glasses, each an 8×7 grid of panels → 30,240 panel images (727×359, uint16 luminance); 11,928 panels contain at least one visible defect; 5,736 unique visible defect instances (19,531 panel-level instance records, because a defect spanning several panels is recorded on each of them; 1,675 instances are rejects under the author thresholds), class counts spot 2,600 / line 2,131 / region 638 / gradient 187 / band 180, eight subtypes.
- **Per-instance labels.** Dense semantic mask (6 classes), instance id, bounding box, subtype, extent, polarity, SEMU visibility, two reject labels (author / expert-consensus thresholds), process step, tool id, fault mode, time window, target cycle and route-graph node positions. Per glass: a 21-node route graph; two label configurations (default: one tool per subtype; ambiguous-cause: the tool is one of the step's interchangeable tools and recorded only in the route graph).
- **Backgrounds.** 30 real defect-free OLED-mobile panel backgrounds (screenshots of a production inspection viewer, display window cropped to 1090×549 px and resized to 727×359), each with 18 augmented variants reproducing illumination/sensor deviations; all from one inspection line.
- **Splits.** Background-level split (18/6/6 backgrounds → train/val/test; every panel derived from a background stays in its split) is the paper's protocol; a glass-disjoint split for process-trace experiments is provided as a file. A random-panel split is used in the paper only as a leakage control.
- **Errors / noise.** Defects are synthetic; SEMU is computed from the generative amplitude, not measured on real Mura. The realized distribution is capped by the per-subtype amplitude limit (alpha_max), which saturates the rare high-visibility tail. The released generator revision resolves overlapping defects with a class-priority z-order that postdates this data; overlap labels differ on 105 of the 30,240 panels between these files and a fresh generator run (see README, "Provenance").
- **Confidential or sensitive content.** None: no person, device identifier or production record is contained. The real backgrounds are defect-free viewer screenshots that the authors release publicly under the data license.

## Collection process
- **Backgrounds** were taken as screenshots of the inspection viewer during normal operation (23 backgrounds on one day, 7 on the previous day), cropped to the display window. No defect was present in any background.
- **Synthetic defects** were generated by the released pipeline (`generation/`), with per-subtype SEMU-to-luminance coefficients calibrated so that SEMU = 1 is just noticeable; thresholds were set by an inspection engineer and validated by a five-engineer perceptual study (realism 4.5–5.0 / 5; per-subtype threshold elicitation, responses released anonymized).
- **Timeframe.** Backgrounds June 2026; generation June 2026; perceptual study June 2026.

## Preprocessing
- Backgrounds: 5-px top/bottom crop, resize to 727×359, mean/std matching to a reference panel to suppress tiling artifacts, 18 illumination/sensor augmentations per background.
- Defects: multiplicative luminance fields I' = I (1 ± α M); masks from the engineer-visible threshold; panel-instance SEMU = 95th percentile of local visibility over visible pixels.
- Release format: lossless PNG conversion of the generator's arrays (bit-exact; `tools/verify_release.py --src`).

## Uses
- **Intended.** Multi-class Mura segmentation, graded visibility regression, process-trace attribution and controlled studies of what signal each task relies on; detection via the YOLO/box exports.
- **Not intended / cautions.** Absolute numbers are not estimates of production performance: all backgrounds come from one line, the low-frequency illumination field is shared by every panel, and the step/tool mapping is a modeling assumption. In a zero-shot check on public real weak-Mura imagery (paper supplement, Sec. S9), models trained only on MuraTrace transferred for the defect family it synthesizes (compact spots) and not for unmodelled camera-domain factors (bezel geometry, sensor grain, pixel pitch); users applying the models to another camera domain should add that camera-side knowledge themselves.
